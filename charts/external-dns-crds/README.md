## Scope

The `external-dns` chart ships the same CRDs in its `crds/` directory. Helm installs those files once and never upgrades or removes them, as documented in the [Helm CRD best practices](https://helm.sh/docs/chart_best_practices/custom_resource_definitions/).

This chart holds the CRDs as regular templates instead, so that `helm upgrade` applies CRD changes and `helm diff` shows them. Use it when you manage the CRD lifecycle yourself, for example with a separate release, a different RBAC scope or a GitOps stage that runs before the controller.

Both charts carry the same version, so `external-dns-crds` version `x.y.z` holds the CRDs of `external-dns` version `x.y.z`.

## Installing the Chart

Before you can install the chart you will need to add the `external-dns` repo to [Helm](https://helm.sh/).

```shell
helm repo add external-dns https://kubernetes-sigs.github.io/external-dns/
```

Install this chart before the `external-dns` chart. The `crds/` directory of the `external-dns` chart is then a no-op, because Helm skips CRDs that already exist.

```shell
helm upgrade --install external-dns-crds external-dns/external-dns-crds --version 1.22.0
```

### Adopting Existing CRDs

Helm refuses to install a CRD that already exists without its ownership metadata. If the `external-dns` chart, or any other tool, installed the CRDs first, label and annotate them before you install this chart.

```shell
for crd in dnsendpoints.externaldns.k8s.io dnsrecords.externaldns.k8s.io; do
  kubectl label crd "${crd}" app.kubernetes.io/managed-by=Helm --overwrite
  kubectl annotate crd "${crd}" \
    meta.helm.sh/release-name=external-dns-crds \
    meta.helm.sh/release-namespace=<namespace> --overwrite
done
```

## Uninstalling the Chart

The CRDs carry the `helm.sh/resource-policy: keep` annotation by default, so `helm uninstall` leaves them, and the custom resources, in the cluster. Set `keep: false` to let Helm delete the CRDs, and every `DNSEndpoint` and `DNSRecord` with them.
